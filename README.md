# 航域 AeroPlan

面向 DJI Dock 3 / Matrice 4D、4TD 的网页航线预规划工具。用户在 Cesium 地图上绘制作业区，页面自动生成垂直摄影航线、拍照位置和区内连接路径。

在线访问：[航域 AeroPlan](https://marky789.github.io/aeroplan-ortho-planner/)。

## 本地运行

需要 Node.js 22.12+ 或 24+。

```sh
npm install
npm run dev
```

打开 http://127.0.0.1:5173/ 。天地图浏览器密钥已保存在本机 `.env.local`，不写入规划导出文件。更换密钥时参考 `.env.example`，然后重启服务。天地图和字体服务需要网络，字体不可用时采用系统字体。

```sh
npm test
npm run build
npm run preview
```

生产构建输出至 `dist/`，预览地址为 http://127.0.0.1:4173/ 。应部署整个目录，包括其中 `cesium/` 下的静态资源。浏览器须支持 WebGL。

## GitHub Pages 部署

推送到 `main` 后，`.github/workflows/pages.yml` 自动执行算法测试、构建、部署路径测试并发布。Pages 使用 GitHub Actions 作为发布来源。

- 项目路径由 `VITE_BASE_PATH=/aeroplan-ortho-planner/` 指定；Vite 资源、规划 Worker 和 Cesium 资源统一使用此路径。本地开发默认 `/`。
- 天地图浏览器密钥配置于仓库 Actions Secret `VITE_TIANDITU_TOKEN`，构建时注入，不提交 `.env.local`。这是浏览器端访问密钥，会出现在公开网页资源和天地图请求中；如密钥设置域名限制，需要允许 `marky789.github.io`。
- 修改部署路径后，应使用相同环境变量执行构建、测试和预览。例如 PowerShell：

```powershell
$env:VITE_BASE_PATH = '/aeroplan-ortho-planner/'
npm run build
npm run test:deployment
npm run preview
```

此时本地预览地址为 http://127.0.0.1:4173/aeroplan-ortho-planner/ 。结束后移除该环境变量即可恢复根路径构建。

## 操作

1. 点击“绘制作业区”，单击地图添加顶点，以 Enter、右键或“完成绘制”结束。Esc 取消，Backspace 撤销当前绘制点。完成后可拖动外边界点。
2. 点击“排除区”绘制内部孔洞；连接线会绕开孔洞。排除区必须完全位于外边界内，不能相交或接触。
3. 选择实际相机模式，修改对地航高、航速、重叠率和建筑高度，系统自动重算。可手动调整主航向或启用交叉网格。
4. 点击“拍照点”显示采集位置，点击“航线预览”播放压缩时间的轨迹示意。3D 按输入的地面参考高度抬升航线，未显示真实建筑。
5. 导出规划 JSON 或拍照位置 CSV，预览后下载或复制完整内容。JSON 可以再次导入；草稿保存在当前浏览器本地。若内嵌浏览器不接收下载，可复制完整内容保存，或在常规浏览器中打开本地地址下载。

支持单个 GeoJSON Polygon，包括内部环。`examples/深圳示例作业区.geojson` 可用于导入演示。已声明的坐标系仅接受 EPSG:4490 或 EPSG:4326 经纬度；WGS84 经纬度按近似位置导入并提示未做测绘级基准转换。GCJ-02、BD-09、墨卡托米制坐标需要事先正确转换。

## 坐标和底图

- 天地图地理坐标服务：`img_c + cia_c` / `vec_c + cva_c`。
- `TileMatrixSet=c`，服务能力文档标注 EPSG:4490；矩阵 1 为 2×1 个 256px 瓦片，对应 Cesium level 0。
- Viewer、Globe、椭球地形、地理投影与瓦片方案统一采用 CGCS2000 的 GRS80 椭球。
- 航线计算先转入以测区中心为原点的局部等距方位投影，以米为单位运算；不会直接把经纬度差当成距离。
- 高度均相对用户指定的测区参考地面。3D 展示暂把参考地面置于椭球 0m；它不代表真实海拔或飞行器可执行高度。

## 航线算法

多边形校验 → 局部米制投影 → 相机近似足迹 → 扫描线与所有内外边界求交 → 往复排序 → 狭窄突出部平面足迹补充 → 可见图最短连接 → 拍照位置与统计。

规则扫描保留凹多边形的所有交段。域内连接通过可见图绕开凹口和孔洞，可贴边行走。自动航向每 15° 试算区内航程与转弯时间；启用双网格时增加正交方向。计算在 Web Worker 中执行。

标称对角视场角与照片像素数用于估算 GSD 和影像足迹：

```text
每米高度的像素尺寸系数 k = 2 × tan(对角FOV / 2) / hypot(像宽px, 像高px)
地面GSD(cm/px) = 对地航高 × k × 100
航线间距(m) = (对地航高 − 最高建筑高度) × k × 像宽px × (1 − 旁向重叠率)
拍照间距(m) = (对地航高 − 最高建筑高度) × k × 像高px × (1 − 航向重叠率)
```

采用垂直摄影、图像宽边横跨航带、机头与航段方向一致的简化模型。相机预设参考 [DJI Dock 3 官方规格](https://enterprise.dji.com/dock-3/specs)。模型未采用完整相机标定，4TD 不同照片模式的标称像素分辨率不等同于实测有效分辨率。

输入规模限制为总计 180 个边界顶点、测区跨度 30km、4000 航段、15000 照片。超出时提示拆分。时间统计包含区内航程和每个航段之间的 3 秒转弯估算，不包含出返场。

## 结果适用范围

此版本完成二维采集预规划，不能凭航线保证“真正射影像”成果。页面与导出文件都明确标注未校核状态。

- 未接入 DSM / 建筑模型，无法判断街巷、立面、高楼遮挡和实际三维碰撞。
- 未做边界外扩、水平安全缓冲、多视角可见性或边缘重叠完整性校核。细长区域补线仅保证简化平面模型的至少一次影像覆盖。
- 机场只作位置和高度标记；机场进出路径、返航、空域、风、电量和分架次需另行规划。
- JSON / CSV 是规划数据，不是 DJI WPML / KMZ 可执行任务。照片点间隔过短时给出提示，未自动规划减速或停悬。

要用于正式城市真正射采集，应继续接入高程与建筑数据、可飞行空间、冗余影像覆盖分析以及真实机型任务验证。

## 实现与验证

- `src/main.js`：界面、草稿、导入导出。
- `src/map.js`：Cesium 地图、绘制、顶点移动、显示与预览。
- `src/tianditu.js`：CGCS2000 WMTS 适配。
- `src/planner.js` / `planner.worker.js`：独立计算引擎。
- `src/planner.test.js`：投影、凹区、孔洞、连接、净空、狭长突出部和异常输入回归测试。

Cesium 固定 1.139.0，并锁定对应的 engine 23.0.1 / widgets 14.4.0，避免不兼容子包被同时加载。升级时应成套验证，并保留 `package-lock.json`。
